# Week 7 Work Checklist — Rehearse the Midterm Path

**Date:** Thu 2026-10-15 to Wed 2026-10-21  
**Team:** 4

> Build a short presentation around what the team can show and prove today. Label anything simulated, incomplete, or unverified. Rehearse before polishing slides.

## Core work — complete all

### Build a believable demo path

- [ ] Start from a clear point another person can reach.
- [ ] Name the target user, the problem, and the one path the demo will show.
- [ ] Write the main demo steps in the reusable [Midterm Demo Script](../student-starter-kit/templates/midterm-demo-script.md).
- [ ] Mark what is working, simulated, incomplete, or unverified. Do not present a mock-up, recording, or plan as proof of a live behavior.
- [ ] Give each speaker a short part, including each student's evidence-backed contribution.
- [ ] Keep one limitation or risk and one realistic next step in the story.

### Check Sprint 1 and current status

- [ ] Complete the Sprint 1 section in [Sprint Quality Quick Checks](../student-starter-kit/templates/sprint-quality-quick-checks.md).
- [ ] Link proof for the end-to-end path or clearly document the blocker preventing it.
- [ ] Check that the README or setup note tells another person how to view or run the work.
- [ ] Create or update one Midterm Prep Issue with an owner, current status, risks/blockers, next actions, and links to the script and proof.
- [ ] Check that shared evidence contains no secrets, private data, or unapproved real-user data.

### Rehearse and record evidence

- [ ] Run a timed 3–5 minute rehearsal from the stated start point.
- [ ] Use the [Midterm Presentation Rubric](../student-starter-kit/docs/midterm-presentation-rubric.md) to choose one strength and one improvement.
- [ ] Update the script and prep Issue with the rehearsal result, current status, proof, and next action.
- [ ] Update the team's one shared Weekly Report; each student adds their own contribution and evidence row.
- [ ] Each student completes a linked [Individual Evidence Receipt](../student-starter-kit/templates/individual-evidence-receipt.md) to support their row.

## Evidence to link

- [ ] Midterm prep Issue with owner, current status, risks, and next actions.
- [ ] Midterm demo script and run steps.
- [ ] Current screenshot, test note, live demo, or recording that supports the claims being made.
- [ ] Completed Sprint 1 quality quick checks.
- [ ] Shared Weekly Report with a row from every student and each student's receipt link.
- [ ] Any blocker or bug Issue needed to explain the current path honestly.

## Stretch menu — optional after the core work

Choose an extension only if the demo path is already clear and fits within five minutes.

### Stronger presentation

- [ ] Ask a person outside the build discussion to follow the run steps without coaching.
- [ ] Rehearse a recovery or fallback if the live environment fails.
- [ ] Make one simple slide that shows the user, problem, and scope boundary.

### Stronger evidence

- [ ] Repeat the main path from a clean start and record the result.
- [ ] Link one important Issue, pull request, commit, or test note at the moment it supports a claim.
- [ ] Check the start instructions from another teammate's device or workspace.
