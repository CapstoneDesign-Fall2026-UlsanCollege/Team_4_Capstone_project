# Team 4 – CampusVibes
## Route from Current Project State to Final Demo

### 1. Current Project State
CampusVibes already has its main user journey and several supporting features.

**Currently available:**
- Landing page and Firebase authentication.
- Dashboard and navigation.
- Discover / Events page.
- Event search and filters.
- Event details.
- Saved Events and Profile.
- AI Assistant and Suggestions.
- Social features.
- Light/Dark theme toggle.

**Current limitations:**
- Events currently use code-based sample data.
- Firestore event loading has not been verified.
- Google Sign-In and Password Reset have not completed testing.
- Local backup demo setup still needs to be tested.

### 2. Our Route to the Final Demo

**Step 1 – Week 9: Verify and Prepare**
- Review and clean up GitHub Issues.
- Test Google Sign-In and Password Reset.
- Verify Firestore event loading.
- Prepare and test the local backup setup.
- Fix critical bugs.

**Step 2 – Week 10: Improve and Retest**
- Resolve problems found during Week 9 testing.
- Retest the main user journey.
- Verify event information and authentication.
- Check the deployed and local demo environments.
- Organize testing evidence.

**Step 3 – Week 11: Final Demo Preparation**
- Complete the final team rehearsal.
- Confirm each member's contribution and speaking part.
- Test the final demo path.
- Prepare backup screenshots and setup instructions.
- Confirm that the application is ready to present.

### 3. Next Checkpoint

**Week 10 – Testing and Quality Review**

We will check:
- Whether Firestore events load correctly.
- Whether Google Sign-In and Password Reset work.
- Whether the local backup demo runs successfully.
- Whether critical bugs have been fixed.

**Checkpoint goal:** Confirm that the main demo journey works reliably in the deployed and backup environments.

### 4. What Could Change Our Plan?

Our plan may change if:

- Firestore connection or permission problems prevent event loading.
- Google authentication or password reset fails.
- The local setup has configuration problems.
- Critical bugs affect the main demo journey.
- Testing or rehearsal reveals unexpected problems.

**Our response:** We will prioritize fixing issues that affect the main user journey. If a feature cannot be completed reliably, we will document the limitation and use a verified fallback instead of adding more features.

### 5. Final Demo Goal

Our final demo will demonstrate that students can access CampusVibes, log in, discover campus events, search and filter events, and view event details.

We will focus on a working, tested, and reliable application rather than promising unfinished features.
