## 1. Project purpose

**What problem are you solving?**

College students often miss events, clubs, and activities because information is scattered across different places, such as bulletin boards, social media, club pages, and campus calendars. Our project combines campus events and club information into one simple web app so students can easily discover activities that match their interests.

## 2. Target users

**Who is this for?**

* Primary user: College and university students
* Secondary user, if any: Club organizers and campus staff

## 3. Smallest useful version

**What is the smallest version that would still be useful?**

A web app where students can view campus events and club information, search for activities, and filter events by interests such as music, sports, and technology.

### Rough user flow — 3–5 steps

**Start → Open CampusVibes → Choose an event or club category → Search or filter → View useful information**

Evidence / sketch link: [sketch]

## 4. In scope

**What are you building this semester?**

* Campus event dashboard with upcoming events
* Club directory with basic club information
* Event search with categories such as music, sports, and technology
* Filters for event type and interests
* Event details such as date, time, location, and description
* Responsive web app that works on desktop and mobile

## 5. Out of scope

**What are you not building this semester?**

* Real payment or ticket purchasing systems
* Complex event management systems
* Advanced social networking features
* Real-time chat between students and organizers
* Advanced AI recommendation systems
* Full club membership management

## 6. Midterm demo sentence

**Our midterm demo will show:**

> A working web app with an event dashboard and basic Events and Clubs sections with search and filtering.

## 7. Final demo sentence

**Our final demo will prove:**

> Students can use one web app to easily discover campus events and clubs that match their interests.

## 9. Risks and unknowns

| **Risk / unknown**          | **Why it matters**                                                | **Plan**                                                                 |
| --------------------------- | ----------------------------------------------------------------- | ------------------------------------------------------------------------ |
| Project becomes too large   | Too many features could make development difficult.               | Focus on the basic event and club discovery MVP.                         |
| Finding reliable event data | Campus event information may not always be available or accurate. | Start with sample/mock data and consider APIs later.                     |
| Limited event categories    | Not enough categories may make filtering less useful.             | Start with a few clear categories such as music, sports, and technology. |
| Limited development time    | We have a limited semester schedule.                              | Divide tasks between team members and track them with GitHub Issues.     |
| Learning new technologies   | Some team members may be unfamiliar with the development tools.   | Learn the basics together and build features step by step.               |
